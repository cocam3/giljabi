# 작업지시서 T-018: CI — PR마다 자동 검사 (초안)

> Claude가 작성하고, Codex가 수행하고, 사람이 승인한다.
> 번호: 기반 작업이지만 기존 번호를 다시 밀지 않으려고 다음 빈 번호(T-018)를 쓴다. ROADMAP에서는 '0. 기반'에 둔다.

## 담당
- 지시서 작성: Claude
- 구현: Codex
- 확인: 임솔
- 브랜치: `feat/T-018-ci`
- 선행 작업: T-001 (merge 완료)

## 목표 (한두 문장)
PR을 열거나 main에 merge될 때마다 GitHub가 lint·typecheck·test·build를 자동으로 돌리고, 결과를 PR 화면에 보여 준다.
merge 후 이 검사를 main 보호 규칙의 **필수 상태 검사**로 걸어서, 검사가 실패한 PR은 merge할 수 없게 한다.

## 배경
- 2026-11-22에 main 보호 규칙의 필요한 승인 수를 1에서 0으로 바꿨다. (Code Owner 경로는 여전히 리뷰 필요)
- 사람 승인이 없는 PR도 merge되므로, "네 명령이 통과한다"를 사람 말 대신 자동 검사로 확인해야 한다.
- 지금 레포에는 GitHub Actions 워크플로가 하나도 없다. (`.github/` 에는 CODEOWNERS와 PR 템플릿만 있음)
- 레포가 Public이라 GitHub Actions 사용 시간에 비용이 들지 않는다.

## 해야 할 일
1. **워크플로 파일** `.github/workflows/ci.yml` 하나를 만든다.
   - 이름: `CI`
   - 실행 시점: `pull_request`(대상 브랜치 `main`), `push`(브랜치 `main`), `workflow_dispatch`(손으로 실행)
   - 권한: 맨 위에 `permissions: contents: read` 만 준다. (최소 권한)
   - 같은 브랜치에서 새 push가 오면 이전 실행을 취소한다. (`concurrency`, `cancel-in-progress: true`)
   - 작업(job) 하나
     - **이름은 `check` 로 고정한다.** 필수 상태 검사에 이 이름이 쓰이므로 나중에 바꾸지 않는다.
     - `runs-on: ubuntu-latest`, `timeout-minutes: 15`
     - 단계 순서
       1. 코드 받기: `actions/checkout`
       2. Node 준비: `actions/setup-node`, Node `24` 하나만 (확정 사항 1), npm 캐시 사용
       3. `npm ci`
       4. `npm run lint`
       5. `npm run typecheck`
       6. `npm test`
       7. `npm run build`
2. **액션 버전 고정**
   - 쓰는 액션은 `actions/checkout`, `actions/setup-node` 둘뿐이다.
   - 각 액션의 공식 저장소 릴리스 페이지에서 최신 메이저 버전을 확인한다. 그 버전의 **커밋 SHA 40자리**로 고정하고, 같은 줄 주석에 버전을 적는다.
   - 예: `uses: actions/checkout@<40자리 SHA> # vX.Y.Z`
   - 태그(`@v4` 같은 것)로만 적지 않는다. 태그는 나중에 다른 커밋을 가리키게 바뀔 수 있다.
3. **키 없이 통과**
   - 워크플로에 비밀값(`secrets`)이나 API 키를 넣지 않는다.
   - `npm run build` 와 `npm test` 는 `.env.local` 없이 통과해야 한다. 지금 코드는 통과한다.
   - 이후 작업(T-009 등)도 키가 없을 때 빌드가 깨지지 않게 만든다. AI 키는 요청을 처리할 때 읽고, 빌드할 때는 읽지 않는다.
4. **실패 확인**
   - 임시 브랜치 `ci/smoke-fail` 에 lint 오류 한 줄(예: 쓰지 않는 변수)을 넣고 draft PR을 연다.
   - `CI / check` 가 실패(빨간 X)로 표시되는지 확인하고 스크린샷을 남긴다.
   - 확인 후 그 PR은 닫고 임시 브랜치는 지운다. 이 오류는 `feat/T-018-ci` 에 넣지 않는다.

## 건드릴 파일
- `.github/workflows/ci.yml`: 새로 만든다. 이 파일 하나만 바꾼다.

## 건드리면 안 되는 파일
- `package.json`(스크립트 포함), `package-lock.json`
- `next.config.*`, `tsconfig.json`, `vitest.config.mts`, `eslint.config.*`
- `.github/CODEOWNERS`, `.github/pull_request_template.md`
- `AGENTS.md`, `CLAUDE.md`, `README.md`, `docs/**`, `data/**`, 기능 코드 전체

## 필요한 데이터
- 없음

## 완료 조건
- [ ] (기능) 이 PR 화면에 `CI / check` 가 나오고 초록색(통과)이다.
- [ ] (기능) `ci/smoke-fail` draft PR에서 `CI / check` 가 빨간색(실패)으로 나왔다. 스크린샷을 이 PR에 첨부한다.
- [ ] `ci.yml` 의 액션 두 개가 40자리 커밋 SHA로 고정되어 있고, 주석에 버전이 있다.
- [ ] `permissions` 가 `contents: read` 뿐이고, 워크플로 어디에도 `secrets` 가 없다.
- [ ] 실행 시간이 10분 이내다. (PR의 Actions 탭에서 확인)
- [ ] `npm run lint && npm run typecheck && npm test && npm run build` 가 로컬에서도 통과한다.
- [ ] AGENTS.md 4장 절대 규칙 위반 없음

## merge 후 사람이 할 일 (임솔, 또는 Claude에게 요청)
- main 보호 규칙(ruleset `main-protection`)에 **필수 상태 검사**를 추가한다.
  - 검사 이름: `check` (GitHub Actions)
  - "브랜치를 최신으로 유지 필수"는 끈다. 켜면 다른 PR이 merge될 때마다 모든 PR을 다시 갱신해야 해서 셋이 쓰기에 번거롭다.
- 추가한 뒤 아무 PR이나 열어서 검사가 통과하기 전에는 merge 버튼이 막히는지 확인한다.

## 하지 말 것
- `pull_request_target` 이벤트 쓰기 (외부 PR이 비밀값에 닿을 수 있음)
- 배포 단계 넣기 (배포는 Vercel이 함)
- 실제 AI를 부르는 테스트나 평가(`scripts/ai/eval.ts`)를 CI에서 돌리기
- 위 두 개 외의 액션 쓰기, 태그로만 액션 버전 적기
- 검사가 실패한다고 `continue-on-error` 로 실패를 숨기기

## 확정 사항 (2026-11-22, 임솔)
1. **CI는 Node 24 하나만 돌린다.** README의 권장 버전(Node 24 LTS)과 맞춘다. 여러 버전을 동시에 돌리는 설정(`matrix`)은 쓰지 않는다.
